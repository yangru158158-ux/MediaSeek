# 发版前自检清单（release-selfcheck）

来源:批 70~76 全部发版验收报告的发现蒸馏(2026-10-26 用户定规矩:
**workflow 验收每版最多跑一次**;跑前先过本清单;发现 high/medium 修一轮
立即发,余账(low/声明类)记入下批候选——多轮验收耗时费 token,不再回头)。

用法:每次触发 release-acceptance workflow 之前,对着本次 diff 逐项过
适用条目;全部通过才准跑 workflow。

## A. 声明与 diff 相符(最高频,占验收发现近半)

1. **计数核对**:提交说明里的一切数字(几处调用点/几条注释/多少项)
   必须与 diff 实际数目一致——`git show --stat` + 目标 grep 复数一遍。
   先例:批71「三处」实为 4 处;批75「两处」漏第三处;批73「~180 条」实 276。
2. **声明的改动必须在 diff 里**:python/批量脚本中途断言失败会把后续
   文件的改动静默吞掉——提交后 `git show --stat` 对着说明逐文件点名。
   先例:批76二修声明改 PeopleView,diff 里没有(断言中断漏改)。
   先例2:批137 客户端提交首次只进了 1 个文件——`git add` 的参数里带了
   一条已被 `git rm` 的路径,整条 add 报错退出,而报错被 `2>/dev/null`
   吞掉;靠 `git show --stat` 对着说明才抓回(未推送,amend 补全)。
   add 的报错不要重定向;暂存后先看 `git status --short` 全是大写再提交。
3. **注释的批次号/史实与 git 一致**:写「第 X 批某修」前 grep 确认该
   改动真出自那个提交;拿不准就写提交 sha。
4. **顺序描述与代码顺序一致**:「先取消再收尾」类叙述,读一遍实际行序。
   先例:批76 catch 里 cancel 排在 finishTask 之后=对 nil 无操作。

## B. 类型与编译(macOS CI 是唯一拦截层)

1. **三目/链式拼接拆步**:三目嵌进 `+` 链会让编译器类型推断超时
   (unable to type-check in reasonable time)——一律拆成 if+append,
   数组显式 `[String]` 注解。先例:批72(688 行)、批74 同型复发。
2. **API 归属三查**:属性属于谁(URLRequest vs URLSessionConfiguration)、
   是否 throwing(FileHandle.write(_:) 非 throwing,磁盘满抛 ObjC 异常
   **崩进程**——用 write(contentsOf:))、非标签元组用 `.1` 不用成员名。
3. **本地 -parse 过 ≠ 编译过**:不在本地 typecheck 集(仅
   QueryUnderstanding/LabelZh 系)的文件——Views、IndexingCoordinator、
   VectorStore、QueryTimePlace——每次改动按本节 1/2 人工过一遍。
   先例:QueryTimePlace .remaining、ModelUpdateView timeoutIntervalForResource,
   都是 CI 拦的,parse 全绿。

## C. 数据库与边界态(改 SQL/标记前)

1. **先查约束再改**:动任何列的语义前 grep 建表 UNIQUE 约束与该列的
   全部消费方(含 Views 层查询)。先例:frame_index 被当标记位,但它在
   UNIQUE(kind,ref_key,frame_index) 键里——upsert 0 行不会覆盖 -1 行,
   双行并排=标记永不清除(批74 high)。
2. **UPDATE 撞约束态穷举**:同 refKey 多行并存(部分提交/半途失败产生)
   时 UPDATE 打成同值会整条原子失败——先 DELETE 冲突行再 UPDATE,
   python sqlite3 同构复现含双行态。先例:批75 high。
3. **恰好相等边界**:丢弃条件是 `>` 时,`==` 态走哪条路?必须可达且
   有消费方。先例:.part==size 发 Range: bytes=size- → 416 永久卡死
   (批76 medium)。
4. **非事务序列化**:serialized 是队列锁不是事务,块内多语句可半途
   残留——每条语句独立成立才有无害性论证。
5. **改模型包结构/槽位/在线分发:指纹两端同规,服务端先行**:内容指纹
   的拼法在 export_models.yml(生成清单)与 ModelManager.installedFingerprint
   两处,改一处必须同步另一处。客户端依赖新包结构时,先重发在线源,用
   Range 探针读 zip 中央目录验证(根目录、各槽位 meta、清单指纹),对拍
   「已装设备旧指纹」逐段相等后,再发客户端。先例:批137(2.0)去 Base——
   完整包指纹去掉 I 段,本地用假 zip 实跑清单脚本对拍通过后才推送重发。

## D. 并发与回调

1. **完成校验用磁盘真相**:Task{@MainActor} 跳转无顺序保证,内存计数
   可能滞后——最终一致性判断读文件实际大小,不读计数(批76 low)。
2. **声明的取消要真生效**:cancel 排在状态清理之后=对 nil 无操作;
   且主动 cancel 的回声回调要吞掉,不吞会误伤下一轮 continuation
   (批76三修 medium)。

## E. 对称面(用户铁律的执行检查)

1. **改绑定/查询要 grep 旧名全库**:修一处 UI 绑定,同名绑定在别的
   View 还有几处?先例:批75 修了 LibraryView 漏 SearchView 横幅。
2. **改裁决语义必须升盐**:归组/识别逻辑的输入集变了(查询放宽/阈值
   改),算法盐同步 +N,否则旧快照复活旧判决;注释同步新盐号
   (批76 a21→a22)。
3. **删守卫后清悬空引用**:grep 被删符号名,注释里的历史引用补上下文
   (批71「上方 guard」悬空)。
4. **动 search() 路由/地点代码,四形态×四页签必核**:裸地名(南京)、在X+
   内容词(在杭州 猫)、多词含地名(杭州 猫)、结果内,各过一遍 全部/照片/
   视频/文件 页签——新分支条件是旧条件的超集 = 静默吞掉旧形态:批103 换
   交集门埋掉 e13a4c9 裸地名教义(「加法不是过滤」),12 天后 293 装机才爆
   (批135 复原);批135 一修又漏搬 f219edf 的页签守卫(验收 medium)、
   丢掉批99 四通道的文字栏(294 装机,批136 补)——**恢复旧设计要连守卫
   和通道一起搬**;「路径不变」类声明必须对照真实代码逐行核验,不能凭
   记忆写(批118 假前提教训)。

## F. 流程纪律

- workflow 验收每版**一次**;跑前自检留痕(本清单哪几条适用、结论);
- 验收后:high/medium → 修一轮(parse+CI 绿)即发;low → 记入
  `批NN 候选`(memory 的批记忆),下批带走;
- 提交说明写「修了什么+先例引用」,不写宣传语——验收员逐句对 diff;
- 装机验必含裸地名查询:搜一个已知城市(如南京),结果应为该地拍摄
  全量 + 📍标签 + **文字栏非空**(OCR 文字命中,批136 起);diag.log 应出
  「地点[...] 路径=纯浏览」与「地点[...] 文字栏=N」行、无该城的语义行
   (批135 起路由可见);照片/视频/文件页签各点一遍不互混。
- 装机验必含复合标签中文词(批142 起):搜一个下划线标签的中文名(热气球 /
  洗衣机 / 成年猫 / 花田——挑词集里只有整键的;**别用「蓝天」**,它的词集
  还有 sky,修复前带 sky 的牌就能命中,看不出变化),diag.log 的「通道[…]」
  行里 **标签=N 应 >0**(批142 前这类词恒为 0:词集里是整键 balloon_hotair,
  匹配却要求 balloon、hotair 两个片段)。张数可与「设置→图像模型词汇」里
  该标签的张数对一下。搜 无人机 / 音箱 / 冰球 这类同名多键的词(整词,或
  放进短语如 无人机表演),**完全退出 App 重开再搜,两次结果应一致**(批142
  前反查表先到先得、随字典遍历顺序漂移)。
- diag.log 两行明细(批143 起,全局搜索才记;排查「标签=N / 视觉=N 是什么
  构成」时先读它们,别只看通道行的总数):
  - `标签明细[查询] 照片N: 词=张 … | 视频M: 词=张 …`——标签通道命中的是哪
    些牌词、各多少张照片/视频(同一照片/视频多行只算一次)。先例:3 (2) 装机
    搜 balloon_hotair 标签=56 对 热气球 标签=7,差的是 balloon 牌(英文键拆
    片段顺带命中),通道行只有一个总数看不出来。
  - `视觉明细[查询] 串=<送进 SigLIP 的查询串> 一档0.261=N 二档0.157=N [三档…]`
    `尾线后=N 牌词分布=screenshot=38 text=20 …(前 12 个词,各挂在多少个命中上)`
    `无牌=N 头部=P0.171:screenshot,text | V0.165:outdoor,sky …(前 8 个,P=照片`
    V=视频帧)——各档地板与命中数、幸存命中的牌词分布、头部几个的分数与前 3
    个牌词。先例:3 (2) 装机 搜 无人机 视觉=42 全是截图/文档,分数带与真证件
    照重叠,没有牌数据定不了修法。记分布不逐条列:diag.log 超 500KB 是整份
    删除,逐条列 30 个×5 词约 1.5KB/次,三四百次搜索就把之前的日志全挤掉
    (批143 验收 low);分布一行约 400 字节。
- 词条同解(批143 二修起;用户定「两个都精确」):**整个查询就是一个词表里
  的键时,标签通道按它的中文名处理**——打 balloon_hotair 与搜「热气球」、
  打 billboard 与搜「广告牌」、打 document 与搜「文档」词集相同。多词查询
  不走这条(手敲 `machine beach` 照旧剔 machine);词表外的下划线串(id_card)
  照旧拆。核对:任选几个词条,打英文键与搜中文名,「标签明细」里的牌词应
  相同。中文名一侧只动了 冰淇淋/客厅/游乐园 三个词(各去掉一个词典短语拆出
  的牌:ice/room/park)。
- 裸搜多词(批144 起,用户定「捞得多的词收尾线」):搜 猫咪 小狗 这类两个常见
  词,结果应与「语义:猫咪 小狗」同量级(几个到十几个),不再是上千;diag 应有
  「AND尾线[词] 宽召回=N 收尾线后=M 线=x」行。弱词组合(阳光 海滩)不应变少
  ——宽召回不足 30 个的词照旧免尾线。先例:3 (3) 装机 猫咪 小狗=3,019 几乎
  全错(批103 的「交集即精度」对常见词不成立:每个词宽召回≈全库前 4000)。
- 概念词截图抑制(批145 起,用户定「做」):搜 无人机 / 热气球,diag 应有
  「截图抑制[查询] 尾线后=N 剔除截图=K 余=M」行,且界面语义栏不再是一屏文档
  截图;搜 文档 / 微信 / 信用卡 / 身份证 **不应出现**这一行,结果数与之前相同
  (不适用:无标签词、截图族/设备族/人像族/平面物族、卡与证件豁免)。背景:SigLIP
  把文档截图打到 0.16~0.19,刚过第二档线——3 (3) 装机 无人机 46 里 40、热气球
  3 里 2。只管弱档命中(过一档强线 0.261 的照留)、只管全局非交集路径。
- 裸搜多词=词分流(批146 起,用户选「混合方案」):画面词合成一句走单词语义
  阶梯+尾线,整句命中算作每个画面词的证据;人名/专名/数字/地名/文字证据照旧
  逐词求交;标签牌必须全部画面词都命中才算(不按「任一词」放——批41 事故)。
  只对裸搜多词生效,and:/or:/文字:/语义:/原生语义: 前缀不变。diag 应有
  「多词整句[查询] 画面词=N 精确词=M 整句命中=K 结果=J」。装机逐形态核:
  ①画面词组合 猫咪 小狗 → 几个到十几个,接近「原生语义:猫咪 小狗」,卡片标
  「整句相似」;②人名+内容 杨如 电脑 → 仍是他本人的电脑照;③无「在」的地名+
  内容 杭州 猫 → 仍是在杭州拍的猫(有 📍);④数字+内容 → 仍靠文字;⑤and:猫咪
  小狗 → 仍是严格「同时命中」(与裸搜不同);⑥文件页签多词 → 仍只有文字命中;
  ⑦结果内多词 → 同规则限定在结果集内。已知取舍:「猫 沙发」「宝宝 老公」从
  「必须同框」变成按整句相似度排序。
- **发版成功以 altool 的实际输出为准,不以 run conclusion 为准**:altool 报
  ERROR 时退出码仍可能是 0,workflow 照样 success 并打出「已上传」。
  dispatch release.yml 之后必须读上传步骤的输出——有 `UPLOAD SUCCEEDED`、
  没有 ERROR 行才算上传成功(批137三修起流水线会据此把步骤判为失败);
  版本号在「打包自检」步骤的 Info.plist 输出里核对;最后以 TestFlight
  实见的构建号为准。先例:批137(2026-11-24)上传被 App Store Connect 以
  403 拒绝(必需的协议缺失或已过期),流水线报成功,我据此误报「2.0 已发
  TestFlight 296」,实际 TestFlight 上仍是 1.0 (295),由用户发现。
- 装机验必含模型区:设置页「端侧模型」三行(文本/图像 so400m/人脸)都
  「已就绪」;在线更新两个包都显示「已装模型与服务端一致,无需重装」;
  在用 so400m 的设备升级不得触发**照片**全量重嵌:diag.log 的启动自动同步是
  「startRun full=false」,且「相位:快扫 xN」的 N 与「完成: 处理M」的 M
  是新增照片的数量级(个位到几十),不是全库(上万)。别拿「有没有出现
  快扫/照片富集相位」当判据——库里有新照片时正常增量也走这两个相位
  (批137 装机实锤:快扫 x10、处理 15,不是重嵌);也别写成「无 startRun
  full」——正常增量也是 full=false,字面核对会误判(批137 验收 low)。
  导入的图片/视频文件若此前没有视觉向量(1.0 换模型时被清),升级后首次
  同步会一次性重做它们,属预期(批137二修)。
  先例:批137(2.0)起 IPA 不含模型、全部在线下载,模型包结构改动只有装机
  才能验证下载→导入→加载整条链路。

## G. 标签通道(改 labelTokens / 标签词典 / 牌匹配规则时;批142 起)

1. **穷举必须是匹配级,不是词集级**:对全量标签逐个断言
   `labelTokensMatchCount(labelTokens(cn), en) > 0` 与
   `labelTokensMatchCount(labelTokens(en), en) > 0`(Swift 与 Python 镜像两侧
   同集)。先例:批142——第四十七批的穷举只断言「词集里有这个词」,而牌的
   匹配是另一段逻辑;批125(5891a7f,2026-11-02)把牌词按下划线拆片段、批126
   (1611fa8)改成片段全中之后,203 个复合键中文搜不上自己的牌,此后 24 天
   测试一直全绿。
2. **修复前后词集全量导出对比**:同一批查询(全量标签中英文 + 短语词典键 +
   事故样本 + **关键词放进短语的样本**)各跑三次,逐个对比词集与匹配结果——
   新代码多次启动逐字节一致;增加的是哪些、减少的是哪些、丢了哪些匹配,
   逐项点名后写进提交说明。先例:批142 首版的查询集 3239 个全是整词,对比
   全绿并据此写了「重启后结果一致」;验收指出短语里的多键名仍随启动漂移
   (medium,只修了整词)。把 25 个多键名放进短语重测:首版 52 个查询在漂移,
   二修后 3367 个查询零漂移。
3. **新断言要验红**:先在旧规则下跑一遍确认变红(记下首个失败词),再改规则
   变绿;镜像侧用变异检验(拿掉修复必须红)。没验过红的断言不算护栏。
4. **史实类注释逐条对 git,别把同类现象写成同一起点**:先例:批142 把 4 条
   同义桥接写成「同样自批125 起失效」,实际 document→printed_page 自批125、
   其余 3 条自批126 起(批125 那版片段有交集就命中,sky 能碰上 blue_sky)。
5. **补全/放宽类改动沿用既有判据,不另立条件**:批142 二修沿 termCoverage
   实际捐出的碎片区间补全兄弟键——盖满才捐、嵌套只留最长、单字键整词相等
   三条规则原样生效;若按「原子词包含多键名」补全会打穿嵌套(「生日蛋糕」
   带入 cake_regular,镜像变异检验实锤)。
6. **词条同解,而且要用穷举断言守住**:用户按词表把 balloon_hotair 与 热气球
   当同一个词条。先例:批143——键打进来时被拆成 balloon+hotair,顺带命中
   balloon 牌(48 个对 3 个);用户定「两个都精确」。首版只做了「词表里的键
   不拆片段」,提交说明就写了「现在同为精确」——验收用镜像逐键对拍:208 个
   复合键里仍有 14 个、简单键里 48 个两侧不同解(中文名一侧多命中同名兄弟
   键/词典译法),而断言只守了 balloon_hotair 一例。二修改为「整个查询是
   词表键 → 按中文名处理」,并加穷举断言 `labelTokens(en) == labelTokens(cn)`
   对全部 1566 个词条(两侧同集)。**规则性结论必须有穷举断言撑着再写**,
   一个样例通过不等于规则成立。
7. **转发/递归类改动先找「归一后又回到自己」的输入**:批143 二修首版在函数
   末尾并入中文名的词集,键 dvd 的中文名是 DVD,小写回去还是 dvd → 自己调
   自己,栈溢出(本机探针崩在第 456 个键,没进 App)。改法=只走一层:中文名
   归一(繁→简+小写)后的任一原子若是词表键,不转发。**判「值是不是键」要按
   归一后的形态比**,大小写不同的名字(dvd/DVD、suv/SUV,全表只有这两对)肉眼
   和大小写敏感的查找都看不到。排查手段:逐键调用、调用前先把键写进进度
   文件,崩在哪一目了然。
9. **「只对同一个词条生效」的规则,判据不能取自整条查询**:批143二修的
   「短语撞词条键不拆词」按整条查询的译词集合判,多词查询里别的词捐出的同形
   词被一并丢掉(「猫咪 成年猫」丢 cat、「跑车 警车」丢 car,穷举 255 对词
   86 个丢牌),丢弃与否还取决于单值反查表先捐出哪个键(「热狗 狗狗」随启动
   变)——两条 medium。修法=逐原子逐区间判、键全集表取判据。**对比集与断言
   必须含「关键词两两组合」**(单词同解的穷举断言抓不到这类);断言用不变量
   「多词查询的词集 ⊇ 各词单独时捐出的同形片段」。
8. **同一判定有「计数」和「取词」两个出口时共用一处实现**:批143 把牌词
   命中判定收进 `labelTermMatches`,`labelTokensMatchCount` 与
   `labelTokensMatchedTerms` 都调它;两侧穷举断言二者对全量标签×两个方向恒
   一致。两份各写一遍的规则迟早漂移(批125/126 的来回来去就是)。
